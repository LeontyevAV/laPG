# laPG

## Архитектура

- Главный модуль: `main.py` (меню 11 пунктов, включая Web UI)
- Функциональные модули: `backup.py`, `restore.py`, `db_utils.py`, `settings.py`, `cron.py`, `compare.py`, `remote.py`
- Web UI: `web/app.py` (FastAPI + Jinja2 + HTMX), `web/templates/`, `web/static/`
- Взаимодействие с PostgreSQL через CLI-утилиты (`pg_dump`, `pg_restore`, `psql`, `createdb`, `dropdb`) — `subprocess`
- `asyncpg` используется только для получения списка БД с сервера
- SSH: key auth preferred, password via `sshpass` (in-memory dict `_ssh_sessions`, never on disk)
- SQLite на удалённых серверах через `python3` + `sqlite3` (не требует `sqlite3` CLI)

## Команды

```bash
# Главное меню
python main.py

# Бекап (интерактивный выбор БД)
python backup.py
# Бекап всех БД параллельно
python backup.py --all

# Восстановление
python restore.py

# Web UI
python run.py
# или
uvicorn web.app:app --host 127.0.0.1 --port 8080
```

## Конфигурация

**`.env`** — только секреты:
```
DB_PASSWORD=your_password
```

**`settings.yaml`** — все остальные настройки:
```yaml
connection:
  host: localhost
  user: postgres

backup:
  default_compress: 0
  default_keep: 0
  databases:
    labots:
      compress: 9
      keep: 20

restore:
  backup_dirs:
    - backup
    - restory

scheduler:
  enabled: false
  cron: "0 2 * * *"

web:
  host: 127.0.0.1
  port: 8080
  enabled: true

servers:
  - name: main
    host: 82.97.248.238
    user: root
    port: 22
```

`.env` имеет приоритет над `settings.yaml` (DB_HOST/USER из `.env` переопределяют `connection`).

## Структура

- `main.py` — главное меню (11 пунктов)
- `backup.py` — создание дампов (интерактивный и `--all` режимы)
- `restore.py` — восстановление из дампа (включая SSH-туннель и remote PG password prompt)
- `cron.py` — управление cron (чтение/запись crontab, перезапуск)
- `db_utils.py` — общий модуль: получение списка БД, ротация бекапов
- `compare.py` — сравнение схем БД (full structure, table listing, column diff)
- `remote.py` — операции на удалённых серверах (top processes)
- `settings.py` — загрузка и модель конфигурации (pydantic + YAML)
- `settings.yaml` — конфигурация (пути, ID, флаги, списки, servers, web)
- `.env` — секреты (пароль)
- `run.py` — entry point для Web UI
- `web/app.py` — FastAPI приложение (dashboard, backup, restore, servers, SQLite browser)
- `web/templates/` — Jinja2 шаблоны
- `web/static/style.css` — стили
- `backup/`, `restore/` — директории с `.dump`-файлами
- `tmp/` — временные/тестовые файлы (в `.gitignore`)

## Соглашения

- Дампы в формате custom (`-F c`) с именем `{db}_backup_{timestamp}.dump`
- Список БД получаем через `asyncpg` с fallback `postgres` → `template1`
- `--keep N` — удаляет старые дампы, оставляя N последних (по дате в имени файла)
- Восстановление: drop + create + pg_restore
- `backup.py`/`restore.py` импортируются из `main.py` без исполнения (guarded by `if __name__`)
- Настройки: `.env` (secrets) + `settings.yaml` (всё остальное), мерж через `settings.py`
- Web UI: FastAPI + Jinja2 + HTMX, без JS-фреймворков и build-шага
- SSH: пароль хранится только в памяти (`_ssh_sessions` dict), при перезапуске теряется
- SQLite: boolean колонки — INTEGER 0/1, в таблице ✅/❌, в редакторе checkbox + hidden 0
- Row identification в SQLite через `rowid` (или `_rid` из результата)
- Temp-файлы в `tmp/`, добавлены в `.gitignore`
